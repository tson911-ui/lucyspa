# UX/UI Redesign Step 5: App shell, navigation, auth layout

Status: CLOSED / OWNER APPROVED; auth layout corrected afterwards on Owner request (card on a full-screen brand background); that correction and the auth-card UX review below are awaiting Owner review and are uncommitted. Not deployed. Contract: `UXUI_REDESIGN_DESIGN.md` 4, 12.6 (updated), 13. Owner feedback included: workforce auth pages no longer look bare (first a split layout, replaced by the card on a full-screen brand background).

## What changed

- `packages/ui` (new, tokens only, text via props): `AppShell` (desktop sidebar collapsible to icons, remembered in `localStorage` as a convenience; tablet icon rail that expands as an overlay with scrim and Escape; phone drawer; sticky topbar with a reserved gap for a later search), `SidebarNav` (groups, empty groups hidden, one-item group flat, `aria-current="page"` plus fill and edge bar), `UserMenu` (avatar, name, title, links, sign out; closes on Escape, outside press or link), `ThemeToggle` (Light/Dark/System radio group, cookie from Step 2), `Breadcrumbs` (component only; wired on detail pages in Steps 8-10), `shell.css`, 13 nav icons.
- **Auth layout** (`AuthLayout`, `BotanicalPattern`): the centered card of before Step 5 (width 26 rem, wordmark LUCY SPA at the top inside the card) on a **full-screen brand background**: deep brand-red gradient plus inline-SVG botanical line art at 8% opacity, identical in light and dark. The card uses the normal surface tokens (light card in light mode, dark card in dark mode). Language link and theme toggle stay at the top right of the page, restyled with the `--ls-auth-panel-*` tokens so they and their focus ring read on red. Phones: same background, card with side margins, smaller padding. No image file, no external request, no animation; the background is `aria-hidden`; a photo can replace it later.
- **Auth card UX review** (background, card position and top-right controls unchanged): (1) the "Đăng nhập bằng" radios became `SegmentedControl` (Mã nhân viên | Email), a radio group with one tab stop, arrows/Home/End, equal-width wrapping segments, 44 px targets; its name is an `aria-label`, not a visible legend. (2) One vertical rhythm from spacing tokens: 16 px between blocks, 8 px title to intro, 20 px intro to form; the legacy fieldset margin that caused the oversized gap and the offset label is gone (forgot-password's intro moved out of its form to match). (3) 24 px between the wordmark and the title. (4) "Quên mật khẩu?" moved to the right end of the password label row (`Field` gained an optional `labelAction`, rendered outside the `<label>`). (5) `PasswordInput` (eye / eye-off icon, button named "Hiện mật khẩu" / "Ẩn mật khẩu", value kept, never submits) on login and on the new-password and confirm fields of forgot-password. (6) Card elevation from a new `--ls-auth-card-shadow` token with separate light and dark values, so it shows on red in both themes.
- **Auth card review 2** (Owner): (1) `SegmentedControl` lost its border: neutral track, selected option = solid brand fill with on-brand text (both themes) carried by one sliding thumb (`--seg-index`, 250 ms ease-out); (2) shared **motion tokens** (`--ls-dur-fast/base/slow` 150/200/250 ms, `--ls-ease-out`, `--ls-press-scale`; all zero under reduced motion) used by button hover/press, input focus (ring eases in, also on the auth card inputs), nav hover and the segmented slide; recorded as decision D13 and 6.6 (micro-interactions only). (3) **Dev overlay "1 Issue"**: reproduced on a language switch; React logged "Encountered a script tag while rendering React component" because the root layout's pre-paint `<script>` was re-created on the client when the locale segment changed. New `ThemeInitScript` renders it in the server HTML and never creates it on the client (`useSyncExternalStore` server/client snapshot); `next/script` did not fix it. Verified in the running dev server: no console error after the switch, script still in the HTML. Also set the auth card title to weight 600.
- Web: `WorkforceShell` now renders `AppShell`; groups and icons come from `lib/workforce/nav-groups.ts`. Personal pages (My account, My income) moved to the user menu; theme and language are in the topbar from 640 px and inside the user menu on phones. Login and forgot-password (the only workforce auth pages) use `AuthLayout`; the language switch moved to `LanguageSwitch`. The tagline (`auth.tagline`, approved) is no longer displayed, since the brand panel it lived in is gone; the dictionary key is kept.
- Regrouped navigation per contract 4.2: Overview, Operations, Sales & payments, People, Catalog, Administration (Website group arrives in Step 11). Dead `wf-topbar/nav/body/menu-button` CSS removed; `.wf-app`, `.wf-main`, `wf-login*` stay (pages and customer auth still use them until Step 10 / Part 2).

## Migrations / permissions / API

None. `navigationFor` rules and order are untouched; only `NavItem.group` values changed (`home/operations/management` to the seven task groups). The dashboard shortcut grid keeps the same pages through `isManagementItem` until Step 7 removes it.
